# Changelog

## Unreleased

## 2.0.0 — 31 October 2026

- Briefing: add the Weak signals module (low-coverage stories that also carry a major rating, a link to a big thread, rising momentum or a named industry impact) and the Forward watch module (scheduled, expected and conditional lines quoted from cited reporting, with the date exactly as the publisher wrote it).
- Briefing's strategic impact modules: Regions lists each region with stories and filters the whole board when you select one, region tiles show the busiest stories under each region, Industry impact groups the sectors cited passages name, What drives World Tension shows each event type's severity beside its coverage, and the escalation timeline follows the lead story's turning points.
- Briefing gains an executive sitrep, a since-your-last-briefing summary, priority development cards and the lead story's source footprint. Sitrep lines restate cited highlights on this Mac, fall back to the highlight itself, and are cached only while their inputs are current (library schema v29).
- Briefing is now a board of modules under five questions, from what is happening now to what to watch next. Customize Briefing chooses which modules show and their order, and World Tension shows its 7-day change.
- Briefing design documentation now follows the approved modular war-room design: five pillars of optional modules, a Customize Briefing sheet and shared honesty rules; the outdated situation-board mock and its image are retired (#847).
- The native UI QA script compiles against main again: Settings no longer reaches into the app's entry-point type for the backup and restore actions, which now live in their own file.
- A feed refresh redraws only the cards whose story, coverage or selection changed; every visible card used to redraw each time the list updated.
- Marking a story read or unread no longer rescans the library for counts, the muted-story count is reused until the library changes, and event summaries use their index.
- A story whose publisher changed its text, or whose classification was refused, is classified again instead of waiting for a relaunch.
- A page declared as UTF-8, or an undeclared page whose bytes are mostly valid UTF-8, keeps its UTF-8 text when it has a stray invalid byte or a prefix cut inside a character, instead of decoding as Latin-1.
- Lead-image lookups record publisher pages that refuse the request (HTTP 403, 404, 410) as having no image, so they are not requested again on every pass.
- Classifier categories are stored only with the story's enrichment, no longer in the publisher's own category: Clear AI Analysis now really clears them, and a refresh no longer rewrites the publisher value and its full-text entry back and forth with each classification. A schema v28 step clears the publisher categories that held the classifier's value (all of them for a library older than schema v22, whose hints v22 had replaced with classifier labels). A feed that sends a category restores it on its next fetch; a story no longer in its feed keeps it cleared and shows the classifier's category (#817).
- Paywalled publisher pages that answer HTTP 401 or 402 open in the subscriber-only reader state instead of showing an HTTP error.
- Notification images up to 10 MB are accepted as the privacy policy now states, and the app's privacy manifest also declares reading file dates for the backup folder you choose.
- Notification bookkeeping and retention clean-up each run in one transaction, so a quit mid-way never counts a banner without announcing its story.
- Opening an event's overview no longer marks its representative story read, so the unread count and the Unread list only drop for stories you actually open.
- Restoring a library now rebuilds the saved-stories Spotlight entries from the restored library at the next launch, so the previous library's stories no longer linger (#812).
- Clear All Caches now also removes story embeddings, matcher signals and event overviews, everything Clear Analysis removes, so it never leaves less cleared than the smaller action (#811).
- The documented network egress now lists the automatic GitHub update check (what it requests, when, and that it carries the app version in the User-Agent plus standard request headers, with no identifier of the Mac or user), and the Updates settings footer says so (#810).
- Scrolling quickly past many images no longer leaves their downloads running: a shared image download now stops when the last card or prefetch waiting for it goes away, and clearing the image cache no longer makes a finished old load discard a newer one.
- Redirect safety tracking is now isolated to each network request, so simultaneous requests in different sessions cannot share redirect state.
- Reloading an open web preview, or retrying a load that failed, reconnects to the network gateway when it has restarted on a new port, instead of failing on the old one; a load that keeps failing is retried once and then reports the error.
- Reset Reading Interests now also applies to notifications, so they stop following the interests you cleared.
- Clear AI Analysis now stops cleared results from coming back: every background write carries the generation it started under and is refused after a clear, and the classification queue starts over.
- Behind the scenes: the update-check and menu bar tests now run the app's own update checker and menu bar text instead of test-only copies, so a regression in either is caught; the menu bar wording itself is unchanged.
- Removing a feed in the catalog or onboarding now works for a subscription stored with a trailing slash, and its health line shows.
- A blocked frame embedded in a publisher page no longer shows the page-blocked banner or stops the progress bar in the web preview.
- The Briefing end-to-end tests now run on CircleCI along with the other test files.
- Four starter feeds that no longer worked (Semafor, ABC News Australia, Smithsonian Magazine and Roll Call) are removed from the catalog and now show as retired with suggested alternatives.
- Feed items whose link is not a web address (for example smb:, file: or another app's URL scheme) are no longer stored, so Open in Browser and the overview's Safari button can only open web pages (#799).
- Shortcuts: the Add Feed action now fetches the new feed at once and shows its status, like adding it in the app, and a failed update check (offline, rate limit, server error) is not retried on every app activation: it waits the same six hours as a successful one, even across relaunches.
- Pasting a feed:// address into Add Feed or importing one from OPML now subscribes to the real feed, and addresses with other schemes (ftp, webcal, file) are refused instead of being saved as a subscription that can never load (#797).
- Feed dates with two-digit years (RFC 822) now land in the 2000s, common zone names such as BST, CET, CEST, IST and AEST get their real offsets, and JSON Feed items with only `date_modified` are dated by it.
- Podcast and aggregator feeds no longer repeat text in story titles and summaries: `itunes:`, `googleplay:` and other non-RSS elements and an Atom entry's `<source>` stay out of the story's own fields.
- Story images published with http:// addresses now load over HTTPS when the same host serves them (every Africanews card, for example), on cards, in the reader and in notifications (#794).
- Article text can no longer break out of the reader-summary or World Tension prompts with a spaced or upper-case closing tag such as `</source_data >` or `</SOURCE_DATA>`.
- The overview warm-up builds from the same reports as the reader and never cancels the overview the reader is waiting for.
- Stories no longer regroup between launches when a reader's "Not the Same Event" verdict sits between two events that each belong with a third; the story pass now links events in a fixed order (#791).
- A report announced before it was grouped no longer lets its event post a second banner when another outlet's report joins it; the announcement moves to the event it joins (#790).
- A story's overview is no longer refused or regenerated on every open after two of its other events merge; overviews follow their own event's version instead of the story's total (#789).
- A feed that empties and answers with no items now has its new cache validators and item counts stored, so News stops sending an outdated ETag and feed health no longer reports the old item count (#788).
- A library that opened read-only (damaged, saved by a newer version, or not backed up before an upgrade) no longer downloads every feed on each scheduled refresh and raises a "could not store" alert each time; the scheduled refresh skips feed downloads, and a manual refresh or the Refresh Feeds shortcut explains that the library is read-only.
- A story marked unread or saved while the library refreshes no longer flips back.
- Unread counts in the sidebar, menu bar and Unread list now agree across the whole library with muted stories left out, and Saved Stories is no longer capped at 500 stories.
- Mark All as Read (the Shortcuts action and per-feed command) now marks only unread stories the reading list shows: stories you read earlier keep their original read time, so History order and the interests that steer Briefing stay intact, and World Tension panel reports no longer appear in History afterwards (#784).

- World Tension: the sidebar, the Briefing strip and the World Tension sheet now show one shared reading and state, so the Briefing no longer says the assessment is unavailable while the sidebar shows a reading. Each state reads the same everywhere: today's assessment, "Keyword estimate", "Reading from yesterday" (or how old it is) with the reason today has none, "AI story analysis is off", "Panel collection is off", "Assessing headlines" and "Assessment unavailable" with the cause. The Briefing strip's trend covers the last seven days instead of the last seven readings, and its driving headlines open their stories. The sheet title follows the design language, its status sits in a caption under the title, problems show as a notice instead of orange text, and its illustration pauses while the window is inactive.

Stories appear as tiles grouped by topic, each with one cited key fact from the event's stored overview highlights, a publisher badge, the publisher count, read and saved state and the story context menu; the progress banner sits at the foot of the board, the World Tension strip carries the board's one intelligence label, and the board scrolls with the masthead instead of in a second scroll view. A Back control in the toolbar, as in the reader, and Navigate › Back return to the section shown before the Briefing.

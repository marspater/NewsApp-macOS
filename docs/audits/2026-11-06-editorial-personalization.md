# Editorial personalization experiment — 6 November 2026

Status: gated implementation for issue #1001, stacked on ranking PR #1048 for issue #999. No production settings, impression hooks or recommendation consumers are enabled. Chronological lists and global importance retain their existing behavior.

The actor owns a private SQLite database and starts disabled on every opening. Enabling is explicit. One impression ID represents one visible episode, with separate rendered, scroll, click and save times. Repeated appearances use fresh IDs; repeated action callbacks are idempotent. Unengaged scrolling closes the episode with a negative reward. Engaged scrolling is neutral. A later return after an unengaged scroll requires a new impression. New actions cannot precede rendering, prior actions on the episode or the global reward clock; future timestamps are rejected against an injected clock.

The profile update is the agreed normalized `gamma * previousUnitProfile + reward * articleUnitVector`, where gamma decays with the explicit half-life. Click/save weights are positive and skip weight negative. Model versions and finite 384-dimensional vectors are checked. Vectorless impressions count toward exposure but cannot fabricate semantic preferences. Profile input is optional in the MMR selector and its weight remains zero unless explicitly requested.

Raw impressions are deleted logically after 30 days on opening, recording, profile access and count reads. This is a logical retention policy, not a promise of forensic erasure from SQLite pages or filesystem snapshots. Disabling stops collection and hides profile output; reset transactionally clears impressions, profile and reward clock. The own-store application identifier, schema version and model are checked before writes; foreign databases and newer schemas are refused. This is a separate experimental store, not a migration of the real library. Callers must use a private owned directory. Production integration needs a compatible migration and lifecycle/energy-policy owner before any collection starts.

Discovery is a deterministic 3/20 allocation with an explicit per-user integer remainder carried between batches. Only adjacent candidates below the supplied baseline exposure are eligible; exposure and stable IDs determine order. Shortage is reported rather than filled with ineligible stories. Adjacency and exposure are inputs, not newly inferred truth.

Independent review found and prompted fixes for neutral-scroll action chronology and idle-store expiry; the 31 deterministic standalone checks passed after those changes. The benchmark uses 1,000 synthetic impressions over 100 articles, including 250 clicks, 250 saves, 250 unengaged skips and 250 neutral impressions. It also compares neutral and profile-informed MMR on 500 constructed vectors and ten topic judgement sets. These are authored controls, not measured user relevance. Numerical weights are experimental inputs rather than shipping defaults. Hardware timing, storage and ranking results are recorded separately after execution.

Before rollout: independently review event/copy-disjoint relevance and Discovery labels, freeze tuning parameters before holdout evaluation, measure storage/update/selection cost on target hardware, provide explicit opt-in/disable/reset UI and bounded lifecycle ownership, and verify accessibility and appearance. No user library, real preferences or saved/read state are used by this experiment.

Local Xcode Debug evidence on Apple M5 / 24 GiB: all 31 personalization controls passed. The 1,000-impression recording/reward loop took 1.512 seconds (1.512 ms per rendered episode plus its optional action) and the SQLite allocation was 1,576,960 bytes. Neutral and profile-informed ranking both average NDCG@10 0.1 and diversity 1 on the symmetric constructed sets; individual topic positions change. This establishes no relevance improvement. This combined loop is not an isolated EWMA microbenchmark, production storage forecast or energy measurement.
